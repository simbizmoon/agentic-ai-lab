# Phase 7C — Frozen-Input Worker Backend Comparison

## Purpose

Phase 7A proved that both OpenAI and local bounded-worker paths execute inside
the live AIRA single-agent pipeline. However, the two independent live runs
produced materially different claim text even when source/evidence/claim counts
were identical.

Phase 7C removes that upstream variance.

## Frozen inputs

A persisted live `result.json` supplies exactly one validated:

- `ResearchRequest`
- `ResearchClaimSet`
- embedded `ResearchEvidenceSet`

The comparison performs no:

- Tavily search
- HTTP reading
- embedding
- evidence relevance reranking
- claim generation
- report synthesis

Only these production worker stages execute:

1. Semantic citation verification
2. Claim relevance evaluation
3. Answer coverage evaluation

## Backends

A: OpenAI production evaluators

B: Ollama / qwen3.5:4b production evaluators

Both claim-relevance paths use the same execution budget:

- max attempts: 8
- max recorded tokens: 8,000
- max elapsed seconds: 60

## Measurements

- exact citation label agreement
- exact claim relevance label agreement
- answer coverage level agreement
- answer coverage score delta
- per-stage wall-clock latency
- production service usage / attempts / recorded tokens
- repeated-run stability

## Fixture policy

Use at least two frozen live artifacts when practical. This avoids drawing a
conclusion from only one particular upstream claim set.

The Phase 7A OpenAI and Local live artifacts are both valid candidate fixtures,
even though both claim sets were generated by the same upstream OpenAI claim
generator at different live runs.

Raw results belong under:

`/mnt/ai-data/experiments/phase7-frozen/`

Do not commit raw experiment JSON.
